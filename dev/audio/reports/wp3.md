# WP3 report: Mac backend + helper build (branch `audio/wp3`)

**Done.** `native/audio/mac/`: the `Backend` for macOS (`backend_mac.{h,mm}`, `devices_mac.mm`, `tap_mac.mm`, `vmic_mac.mm`, `blocklist.inc`, 3-line `main.mm`). It covers: device inventory with forms (built-in data source, terminal type, transport and name rules), roles for Beamer Microphone and its feed, the blocklist (Elgato virtual devices plus Wave Link names) and our own private aggregates hidden. Streams run on HAL IOProcs at 48 kHz float32 (channels mapped, AudioConverter when the device rate differs; the other direction's streams are switched off, so rendering to a USB headset does not start its mic). System capture is a global tap that excludes the helper and the `--exclude-pid` pids (late pids are added to the live tap), with mutedWhenTapped and a tap-only aggregate without auto-start. The reference capture is a non-muting tap of an output device. Render goes to a device, the default output, or the feed by UID. The backend also does: default following, `stream_lost` after 3 s without the device (6 s for the feed), coreaudiod-restart recovery (ServiceRestarted), a 1.5 s IO-stall watchdog (intended to cover sleep/wake), demand from IsRunningSomewhere, mic permission through AVCaptureDevice, and the 300 ms devices debounce. `backend_check.mm` is a harness for the backend alone; `acceptance.py` runs all the WP3 checks.
`native/audio/build-mac.sh` builds the universal `build/mac/beamer-audio`, `backend_check` and `BeamerAudio.driver` (it also stages to `~/Library/Application Support/Beamer/hal-staging`). Objects are cached per arch with `-MMD` deps. No `$HOME` path ends up in a binary (`-ffile-prefix-map`, `-Wl,-S`, and a check that fails the build). It exits non-zero on failure (3 if the engine is missing).
`git mv dev/audio/proto/mac-driver native/audio/mac-driver`: `test.sh` passes at the new path (2205 checks). `live_check.py` paths are fixed and it gains `--feeder native`. The `install-driver.sh` path is left free for WP8. `audio/wp2` is merged (clean).

Not tested: sleep/wake (needs a human); x86_64 execution (no Rosetta); real USB/Bluetooth hot-plug (an aggregate was created and destroyed instead: `stream_lost` came 3.3 s later); the TCC prompts (Terminal already holds the grants).
Mac audio state is the same as before: volume 56/50/alert 100, not muted, built-in defaults (input, output, system), Beamer Microphone at 1.0, unmuted, 48 kHz. The driver was not reinstalled. Only processes I started were stopped.

**Deviations.** A duplex device is reported as two `DeviceInfo` entries with the same key (one per direction), so that channels and form are unambiguous. The backend reports demand raw (no hold) because the engine already holds off for 3 s; with both holds it was 6 s. `err` strings and the `why` of `stream_lost` are `"<§3.3 code>: detail"`. `features()` leaves out `aec` (WP9 adds it). System capture ignores `device` (global tap). `permission("system_audio")` returns `unknown`.

**Needs from other WPs.** WP2: (1) CPU of the send path (2 ms poll loop, encoder complexity, per-packet allocations seen in `sample`); (2) pilot glitches on the received stream; (3) `backend.h` has no include guard: the Mac code includes it only through `backend_mac.h`; (4) "suspect" for system audio cannot tell a denied tap from real silence, since a silent Mac taps digital zero too. WP9: the reference tap lives in `start_stream` (`SKind::Reference`, `exclude_self=false`).
