# WP15 report: the PC's low-latency virtual mic switch, E2E harness fixes (`audio/wp15`)

**Done.** 1. `audio.json` `local.vmic_exclusive` (default false; local, never sent; `store.Stored.vmic_exclusive`).
`helper.command_line(..., vmic_exclusive=True)` appends `--vmic-exclusive`. The service adds it only on
Windows. `set_vmic_exclusive(on)` (also dev command `{"set_vmic_exclusive":true}`): when the value changes on
Windows, the old helper is stopped first (it may hold CABLE Input or a muted endpoint), its streams and flows
are dropped (`close` reason `helper`), and a new helper starts with the new command line. `ready` reopens the
streams. Helper events carry a generation number, so late events from the replaced helper are dropped.
`AudioSnapshot.vmic_exclusive` (+ dev status). View: `MachinePanel.vmic_exclusive_{shown,on,label,note}`, only
on this machine's own panel when it is Windows with VB-CABLE present: "Low-latency virtual microphone" + "About
35 ms instead of 70 ms, but no other app can play into CABLE Input meanwhile." `apply_vmic_exclusive(service,
panel, on)` (does nothing on a panel without the switch). Mac page: the switch is built but stays hidden there
(the model never shows it on a Mac or for a peer). Qt page: a `widgets.Switch` + note under the output row.
FakeHelper (in-process and stdio) reports `vmic_exclusive` when started with the flag on Windows.
2. `dev/audio/e2e/run.py`: the PC's `test_source` command(s) are written before anything else starts. The
harness then waits until the PC's `audio-dev-status.json` names that source (15 s, then a RuntimeError that
says what was seen and what to check). Only then does the timeline set any route. `Ctx.dualsense` is optional:
only `both` needs it, and without it that case alone exits with a message. PHASE2 §8.1/§8.4/§9.1/§9.2/§11.4 updated.

**Deviation (needs a decision).** The brief gates the switch on the helper's features including `vmic_exclusive`.
But the WP12 helper reports that feature only when it was started with `--vmic-exclusive`
(`native/audio/win/backend_win.cpp:189`). With that gate the switch could never appear while it is off. So it
shows on a Windows machine's own panel whenever VB-CABLE is present. The feature is used as a check instead:
if the switch is on, the helper is ready and the feature is missing, the note adds "This version of the audio
helper cannot do it." Cleaner fix (native, WP12's files): always report a capability, e.g.
`vmic_exclusive_capable`, and gate on that. Not deployed; the switch has not been tried on the real PC.
