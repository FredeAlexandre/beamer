## Decisions the operator should know (new in D4)

1. **Guard values**: 3 s without a start PLI, 5 s without feedback on a running stream; `no_receiver` retries
   at 10 s / 30 s / then every 60 s while demand persists (worst case ~3.5 s of camera per minute, status shows
   the error). Refusals with an error code retry only on a state change (no timer).
2. **The guards live in the engine** (Mac helper), so they hold even if Python stalls; Python adds the refusal
   stop and the retry rules.
3. **`not_source` retry**: the sink republishes its `camera_devices` (new `rev`) when its route view's camera
   machine changes after such a refusal while it has demand: the only new wire behaviour.
4. **Link-state loss rule simplified**: the "lost as soon as a newer frame completes" shortcut is gone; the same
   loss rules apply in both states (slightly later loss detection on the link, no false loss at transitions).
5. **Size loop guard**: the same display size refused 3 times in 10 s ends the stream with the `error`
   placeholder instead of asking forever.
6. **i18n `SOURCES` hunk moved from CW7 to CW1**, since CW1 now holds the first camera strings.
7. New dev keys: `camera_refuse` (part, PC side) and `log_time_map` (helper); `camera_test_source` accepts
   `;start_ms=N`; new feature word `camera_synth` (`--dev` Mac helpers only).
