# F3: the two Q1 defects

Fix commit `4394e01` (this report is in the commit after it).

## 1. Test hermeticity
`InTheWindow` (`win_app/tests/test_audio_page_win.py`) and `LocalisedPages` (`win_app/tests/test_i18n_pages.py`)
both build `SyntheticWindow` (`win_app/tests/test_settings_layout_acceptance.py`), which already stubs the
window's listeners, sender and receiver. It now also overrides `_make_audio` so that the window holds no
`AudioService`. A test that needs one sets `window.audio` to a fake, as `InTheWindow` does. The fix works through
this shared base, not through `mock.patch` in each `setUp`: the base is the window's existing hermetic stub, and
every user of it gets the fix (`test_appearance_contrast`, `test_click_focus`, `test_design_tiles`,
`test_scroll_wheel_focus`, `test_style_tiles`, `render_settings_layout`).

Correction to Q1: no unit test starts the helper process. `PcAudio`/`AudioService` construction has no side
effects (no thread, no process, no socket). Only `WindowsApplication.start()` → `PcAudio.start()` spawns
`beamer-audio.exe`. The only tests that call `window.start()` are in `test_linux_start`, and on Linux there is no
audio. So the exposure was an unstarted service object, which changes what the Audio page and the map show.

Other exposure, not changed: about 20 test files build a plain `kvm_bridge_win.WindowsApplication(path)`, for example
`test_pages_win`, `test_pairing_window`, `test_pc_three_machines`, `test_tray_icon`, `test_wide_layout`,
`test_crossing_matrix` and `test_dormant_rows`. On a PC with a build in the checkout, they also hold an unstarted
`AudioService`. None of them asserts on audio, and they pass with the helper present (full run below). I left
them unchanged to keep the shared checkout's diff small. If one starts to depend on audio, use the same fix:
`mock.patch("core.audio.helper.locate", return_value=None)` in `setUp` with `addCleanup`.

## 2. Full stop inside `tr()`
`core/audio/view.py`: the tile's output line and the camera's "watching" line now use `tr("{line}.").format(line=…)`.
This is the idiom `win_app/pages_win.py:554` already uses, so the msgid already existed. `tools/i18n_extract.py`
only adds `core/audio/view.py` to its references in `locales/beamer.pot` and `locales/it.po`, and the Italian
`{line}.` translation is kept. The English text is unchanged, so no core test assertion changed.
