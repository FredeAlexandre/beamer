### Why the two new failures happen
`core/audio/helper.py:locate()` (lines 70-90), when run from source, falls back to
`<repo>/native/audio/build/win/beamer-audio.exe`. Step 2 put that file in the export, so `InTheWindow` and
`LocalisedPages` started a **real** `AudioService`. In the first test, `page.service` is then an `AudioService`
instead of `None` (`test_audio_page_win.py:458`). In the second, the audio map gets real tiles, and their accessible description fails the
pseudo-localisation check. CW8's run had no build output in its export, so these tests passed there.

Isolation proof (same export, `win_app\tests` as cwd, both tests run together):
- with `build\win\beamer-audio.exe` present: `Ran 4 tests`, `FAILED (failures=2)`, the same two assertions;
- with it renamed aside: `Ran 4 tests`, `OK`.

The test-spawned helper did not keep running afterwards: only the installed `C:\Users\Alex\AppData\Local\Beamer\beamer-audio.exe`
was running when I checked.

Defects (not fixed, not camera code):
1. **Test hermeticity** (`win_app/tests/test_audio_page_win.py` `InTheWindow`, `win_app/tests/test_i18n_pages.py`
   `LocalisedPages`). These tests assume that no helper exists, but `helper.locate()` finds the repo's build output. As a result,
   the suite fails on any checkout where `build-win.cmd` has run, and it starts a real helper from a unit test. Proposed fix:
   in those `setUp`s (or in a shared test base), patch `core.audio.helper.locate` to return `None`, or set
   `BEAMER_AUDIO_HELPER` to a missing path *and* make `locate` skip the repo fallback when the variable is set.
   The simplest option is `mock.patch("core.audio.helper.locate", return_value=None)`.
2. **Accessible description built by concatenation** (`core/audio/view.py:662`, `parts.append(output_line + ".")`, from
   `620cfa1` on the audio branch; `core/audio/view.py:871` `watching + "."` for the camera follows the same pattern).
   The sentence's final "." is added outside `tr()`, so the whole string ends with "." after "⟧". With real tiles, the
   pseudo-locale check flags `audio: AudioMap.accessibleDescription: ⟦⟦This PC⟧, ⟦Online⟧.⟧ ⟦Sound plays here⟧.`.
   This is minor: a translation cannot move or change that full stop. Proposed fix: either
   `tr("{line}.").format(line=output_line)` (and the same for `watching`), or make the test strip trailing
   punctuation before its `endswith("⟧")` check. The first fixes the translation issue as well.
