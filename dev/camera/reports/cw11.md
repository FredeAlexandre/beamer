How it works (details in the README):
- **App side**: `camprobe` (CW5's tool, built by the deploy into `native\audio\build\win\`) opens "Beamer Camera" as an
  IMFSourceReader in Alex's session (one-shot scheduled task, as the audio harness's players), classifying every
  frame (`c1` code strip / built-in image / other / uniform) and dumping `t_us class frame ts100us`.
- **Clocks**: one time base, the Mac's `mach_absolute_time` (Mac app `mono`, Mac helper `now_ns`, the strip's
  capture time; checked: Python 3.13's `time.monotonic` on macOS is `mach_absolute_time()`). Mac <-> PC monotonic by
  `clock.py` pings (lowest RTT per 10 s, linear fit); PC monotonic <-> PC wall clock (camprobe) by pairs written
  every second on the PC.
- **Data**: both apps' `audio-dev-events.jsonl` (helper events incl. `camera`, video `stats`, `vcam`, `stream_state`,
  `flow_state`; both rotations), dev status samples, camprobe dumps, CPU/memory on both, pings, action notes.
- **Every run** also checks the §6.5 camera-on invariant (Mac camera on outside PC demand <= 3.5 s / 5.5 s).
- Synthetic cases set `camera_test_source` and wait until the Mac's status names it (§7.4) before the route; dev
  commands only, never `permission_request`, so Beamer.app's camera permission stays `not_determined`.
- Real-camera cases (`cam_start_real`, `cam_latency_real`, and CW10's `cam_lipsync_real`) are only run by
  `run.py real` (pre-flight `--real` requires H1: Camera granted to Beamer.app).

### Pre-flight

Blocking (exit 2 with the reason, nothing runs): PC unreachable; PC clone without the Mac's last product commit
(`core mac_app win_app native locales`); an installed app older than that commit; PC installed helper not
byte-identical to its clone's build; Beamer not running / not in dev mode / status file stale on either side; no
camera part or missing helper features (Mac `video1 camera_capture camera_synth`, PC `video1 virtual_camera`); no
`camera_devices` either way; Beamer Camera not installed/present on the PC or held by an app; **H8** nobody
signed in on lebig; deploy lock held. A run also stops (not fails) if the PC half exits early for H8. Reported only:
Mac camera permission, routes not idle, uncommitted product files of other agents, CW10's file present or not.

## Limits (also in the README)

- A picture corrupt below the strip with an intact strip is not detected (no PSNR oracle in the product); the
  engine's `lost`/`skipped`/`holes` are reported beside the strip checks.
- "helper stop -> encoder stopped <= 100 ms" is a proxy (helper `stream_state stopped` vs `camera stopped`); the
  `stop` command is not logged. CW3 measured 10-14 ms directly.
- "holes > 5 packets with frame type" (soak): the product only counts holes; counts reported.
- Dev commands take effect after each app's 1 s poll (PC: + scp/ssh); analyses use write times and windows.
- `cam_start_real` has no strip: first picture = first AU sent + PC target + 10 ms (estimate).
- The 1080p last-rows check needs ffmpeg on lebig (DirectShow name "Beamer Camera"); without it that check is
  "unmeasured" (verdict `incomplete`, not `fail`), the other 1080p checks (media type, decoder size, 1 IDR) still run.
- `cam_oldpeer` reads the PC log only (asusrog must be on; its own `n_rejected` needs a shell there).
